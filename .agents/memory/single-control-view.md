Use one canonical interface with operational controls arranged in horizontal rows along the bottom. Do not maintain a separate fold, narrow, mobile, or short-height control arrangement unless the user explicitly reopens that work. Hermes is not a separate overlay or rail: its complete status, learning fields, and controls stay permanently open inside the existing Live Comments interface without an extra expand action.

**Why:** The user rejected the right-side operational rail, fold-specific alternate views, a floating Hermes card, and any extra action needed to reveal Hermes details. The immediate requirement is one view only.

**How to apply:** Preserve original control identities and wiring while keeping Context/Radio and Display/CCTV in the horizontal bottom deck. Render Hermes as content within Live Comments with all details already visible. Treat responsive control reflow as separate future scope.
